# 89. Three rescues, and one question still unasked

*Which of the four next steps the programme's own rules allow. ADR 0294.*

## The rules that decide

A test with two halves is failed when either half fails. The result you wrote down before you
saw the numbers is the one that stands. An attack is not defined as "whatever this detector
was built to catch." And a loss is written as a loss.

## What that does to the four choices

The one lane that passed already has a name. Wrapping it in a second name and calling it a
stronger engine would be a claim the result does not support, so that package is not built.
The one look at the recordings already used is not taken. Those recordings were not opened.

The patient tally caught more attacks and arrived later. Its test required both. Building a
new way of placing alerts so the late ones count as a pass would be changing the test after
seeing the score. That is not built.

The bending prediction got quieter and caught fewer attacks. Keeping the old score beside the
new one would hide the attacks the bend lost. That is not built.

The remaining question is the one the plant recordings cannot ask yet: an attacker who moves
level and flow together the way the plant itself does, so no single reading looks wrong. That
attack has to be described in the plant's own units, before anyone generates it, and the
description may not mention the detector's line. It is not described in this note, because the
formula is not in the record and making one up would be cheating. Until that description
exists, the question stays unasked, which is the honest state.

Nothing was measured. Version 1 still stands at eight of twelve.
