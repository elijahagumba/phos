# 179. Five of twenty walked straight past

Imagine the desk in the control room that is allowed to set the plant's limits. Somebody sitting at
that desk raises two limits at once: how full the tank is allowed to get, and how full the bottle is
allowed to get. Both new numbers look completely ordinary on their own. Nobody fakes a reading.
Nobody pretends to be a machine they are not. The gauges keep telling the truth all day.

Does our system notice?

## We promised to find out, and then we did not

On 23 October we wrote down the question properly: exactly which plant we would ask it on, exactly
which eight practice runs, exactly how we would count a miss, and a fingerprint of each of the two
detectors so that nobody could quietly swap one for a better one later. Then we stopped before
running it. That is allowed, as long as the promise stays visible. It stayed visible for seventeen
days.

Today we ran it. Once.

## The answer

There were twenty of these attempts across the eight practice runs. We knew there would be twenty
before we opened anything, because the attempts are laid out by a recipe that was already written
down, so we worked the number out from the recipe first. That way, if the run had come back talking
about a different number of attempts, we would have known it was measuring something else.

**It noticed fifteen. Five went straight past.**

## The part we did not expect

We have two detectors. The older one watches the plant and predicts each reading from the other
readings. The newer one was built specifically because the older one cannot see what the control
system was ordered to do.

On this trick, the two gave **identical** answers. Same misses, same false alarms, same delay, every
figure the same to six decimal places.

There is a plain reason. The newer one knows exactly two things: a machine speaking that has never
spoken before, and a machine looking at something it has never looked at before. This attacker is
the desk that is *supposed* to set these limits, and it looks at nothing unusual. So neither of the
newer detector's two skills has anything to grip, and it quietly becomes the older detector again.

That is worth knowing. It is not a verdict on the newer detector in general, and it does not touch
what it achieved elsewhere. On this one trick it adds nothing.

## Two things this number is not

It is not a score for our system. One pretend plant, one kind of plant language, built by us. A
reader who turns fifteen out of twenty into a percentage and calls it detection has been misled, and
we are not going to be the ones who misled them.

And the false alarm figure, a little over one an hour, happens to be exactly the same figure another
test produced last week. Same recipe, twice the runs, twice the alarms, same rate. It is a property
of how our practice runs are built, not a discovery.

## What it does unlock

Back in October we also designed the detector that would catch this trick, and wrote down that we
were only allowed to build it if the existing ones turned out to miss at least one. They missed
five. So it may now be built, exactly as designed, under its own written promise. It is not built
yet. Today's job was the honest number, not the fix.

## One oddity

The record calls today's result "refused". That is not a failure. The question had two possible
answers and both were real results, so both had to be written down as conditions in advance, and
only one of them could come true. Whichever way it fell, one condition would be unmet, and the
machinery prints "refused" when any condition is unmet. The answer itself is in which condition came
true. This is the second time this has happened, so it is now a known quirk of how we keep records
rather than a surprise.
