# Faults stay faults; stamps stay stamps; work orders stay empty

**What this is:** Sessions C9, D1–D3, and E1–E3. 3W is an offshore-wells *fault*
process type, not a cyber row. Command-behaviour is a declared stamp so a
template *could* read it; today's templates still do not. Narratives walk back
to stored observations. Public command capture is still absent. Fault vs
disturbance can be ordered from evidence *shape* on a fixture. When two
explanations carry the same evidence, ranking is silence. Work orders are an
inlet that does nothing until a fact arrives.

**Why it exists:** Collapsing 3W classes 1–9 to "attack" would be a false
statement. Putting a behaviour deviation on a template without a marker would
be a silent schema lie. Chasing 70% by rewriting priors would be a cheat.
Inventing work orders from process clocks would be another.

## What changed

`is_attack_class` on 3W is always false. The joint table grows by an
*unscored* offshore-wells row: files absent, no invented FP/hour.

Command-behaviour uses the same prefix idiom as graph findings. Known-station
attack vs maintenance remains indistinguishable on untyped known-link facts.
`discover_labelled_command_corpora` is still empty.

One transmitter looks like a fault; plant-wide demand looks like a disturbance
— from grouping, not a new prior. Identical evidence lists raise
`insufficient_evidence` on the *narrative* ranker. The breaking harness still
prints 0/16 and 1/4 apart.

Empty work-order lists leave ranking unchanged. A stamped work order supports
maintenance and contradicts unauthorised control. Command-graph patterns do
not also match that stamp.

## What this is not

Not command 70%. Not 2–3/day. Not a labelled public command corpus. Not
high-reliability explanation split on HAI (HAI is attack/normal, not
"this was maintenance").

through [ADR 0059](../docs/adr/0059-explanation-geometry-and-work-order-inlet.md).
Note 16 is still the public command capture we do not have.
