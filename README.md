# PHOS

PHOS is a research project. There is no company, no product, and no customer yet.

What exists is a measurement record: every figure in this repository reproduces from the code and the public datasets it names, including the measurements that failed.

## Atlas

Atlas is a behavioural detection engine for industrial plants.

It does not use attack signatures. It does not catalogue known-bad behaviours. It learns what a plant usually does — flow, pressure, level moving together — and reports when a reading no longer fits.

When something departs, Atlas holds several explanations at once: sensor fault, maintenance, process disturbance, unauthorised control. It attaches the evidence for and against each, rather than issuing a single alert score.

Atlas does not connect to a control network. It does not actuate anything. It reads exported files and reports what it sees. Where it cannot decide, it says so and stops.

## Where Atlas stands

Measured on HAI, a 79-signal industrial testbed:

- **Recall:** 1.00 — every labelled attack window is covered.
- **False positives:** 646.58 per normal hour (ungated joint model); 53.26 after grouping by physical unit.
- **Precision:** near 0.005.

Atlas catches the attacks. It also flags ordinary operation constantly. It is not deployable.

These numbers are frozen. They are stashed with commit and seed in `eval_runs/log.jsonl`. They do not change without a new ADR, a new harness run, and a new verdict.

## Sentinel

Sentinel is the enterprise / cloud engine. It is planned. It is not built. It is not ready to stand next to Atlas.

Atlas is the work now because it is the only engine that can be measured against real data.

## Why we built our own simulator

Clean, labelled industrial data barely exists in public. PHOS builds its own simulated plants — water treatment, power generation, batch reactor — so Atlas has something to be measured against.

The simulator is proprietary. Its source code is not released.

What is public is the scientific methodology: the ADRs describing how plants are built, how attacks are generated, how randomisation works, and where the simulator is known to be inaccurate. Example datasets generated by the simulator are published with digests, so researchers can run their own detectors against fixed files.

The simulator is a diagnostic tool. Scoring well on it means nothing by itself. Real-world validation is the only thing that matters.

## What PHOS will not claim

- **10× reduction** in false positives.
- **2–3 alerts per day.** Refused.
- **≥70% detection.** Not claimed, not earned.
- **Omniscient visibility.** Atlas reasons over five curated explanations. It does not imply general intelligence.
- **Uncalibrated confidence.** A reported percentage must mean approximately that percentage on held-out data. Atlas does not surface hypothesis confidences as probabilities.

## By 2028

Four things:

1. **Scientific credibility.** Researchers can examine the methodology, reproduce experiments, and challenge the assumptions.
2. **Technical differentiation.** Atlas demonstrates capabilities on genuinely unseen industrial data.
3. **Industrial confidence.** Operators have independently evaluated PHOS technology.
4. **Investment readiness.** PHOS holds defensible intellectual property and independently supported technical claims.

None of these exist yet. They are the objective, not the status.
