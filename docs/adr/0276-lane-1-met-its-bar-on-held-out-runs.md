# ADR 0276 — Lane 1 met its bar on the held-out runs; the gain is attribution

- **Status:** Accepted
- **Date:** 2026-10-21
- **PART:** Atlas, stronger-engine programme, lane 1
- **Depends on:** [ADR 0273](0273-the-stronger-engine-programme-is-declared.md),
  [ADR 0275](0275-lane-1-is-frozen-and-its-held-out-score-declared.md)

## Context

ADR 0275 was committed as `323f732` before this run, with
`phos.atlas.command_consistency` frozen at sha256
`87017fcfeaae94790dd8d461d43793a1f87e15a1460e46d963d47a1ae6d0cc94` and the reader at
`06de74b3c6dd52b613a0a53fd7318cabcf5818496cc33030c18605e0e9f6669c`. The twenty held-out runs
had not been opened. The command checked both hashes, the absence of the output and the presence
of all twenty runs before reading a single held-out file, then ran once in 26.4 seconds:

```
uv run python scripts/lane_1_heldout.py --out eval_runs/build/lane-e/lane1-heldout.json
```

## Decision

**Lane 1's bar is met.** ADR 0273 required strictly more attacks caught within the same budget
and at least one class the frozen engine misses entirely. Both hold, and benign alerts did not
get worse.

| Class | Frozen | Lane 1 | Of |
| --- | ---: | ---: | ---: |
| `recon` | **0** | **20** | 20 |
| `replay` | 9 | **20** | 20 |
| `rogue_command` | 13 | **20** | 20 |
| `liar_offset` | 19 | 19 | 20 |
| `mimic_maintenance` | 5 | 5 | 20 |
| `liar_freeze` | 3 | 3 | 20 |

**Attacks caught within budget: 49 of 120 → 87 of 120.** Benign events drawing an alert: **6 of
40 → 6 of 40**, unchanged. The gain came from `unknown_writer` on 39 events and `unknown_reader`
on 22.

**The reading is the one fixed in ADR 0275 before the run, and it has not moved.** The gain is
**attribution on a simulated plant**: a station behaving in a way training never saw. `recon` is
the clearest case and the most honest — reconnaissance never moves the plant, so no
telemetry-only detector can see it however it is tuned, and the command path takes it from 0 to
20 of 20. That is a capability the frozen engine does not have.

It is also shallow, and this record says so rather than leaving it to be discovered. Both
components ask whether the station is one that spoke in training. An attacker who impersonated
the operator would defeat both completely. **This is not the command-against-physics claim**,
which this corpus cannot pose: `mimic_maintenance` and genuine `maintenance` are physically
indistinguishable in it (`eval_runs/build/lane-e/lane1-development.md`), and the held-out numbers
agree — both engines catch the same 5 of 20, by the signal columns, with the command path adding
nothing.

**Not a result about real plants.** ICSSim is generated by PHOS, so R4 and ADR 0143 make this
diagnosis and not proof. No v1 number moves; v1 stays 8 of 12 and `atlas-v1-consistency` is
unedited. `eval_runs/log.jsonl` was not appended. The result file exists once and the script
refuses a second run.

## Consequences

The programme has its first held-out result, and lane 1 is kept. What it buys is an unknown
master detector that works, which PHOS has wanted since ADR 0034 and has never had on data
carrying both paths. What it does not buy is the thesis.

## What would reverse this

A second run of the command, editing either frozen file, pooling the two components, reporting
attribution as the physics claim, or calling a simulated result a result about a real plant.
