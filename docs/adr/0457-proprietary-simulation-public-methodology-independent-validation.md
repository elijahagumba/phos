# ADR 0457 — Proprietary simulation, public methodology, independent validation

- **Status:** Accepted
- **Date:** 2026-11-17
- **PART:** Simulation engine release strategy
- **Supersedes:** ADR 0455, ADR 0456
- **Depends on:** [ADR 0015](0015-simulated-plants-the-injection-hook-and-the-true-state-record.md),
  [ADR 0016](0016-the-graded-attack-library-flavour-separation-and-the-anti-fingerprint-discipline.md),
  [ADR 0029](0029-synthetic-dataset-library-is-not-a-public-corpus.md),
  [ADR 0073](0073-a-synthetic-command-and-maintenance-harness-that-measures-nothing.md),
  [ADR 0078](0078-the-synthetic-diagnostic-environment-is-constructible-and-answers-its-four-questions.md)

## Context

PHOS needs to satisfy three competing requirements simultaneously:

1. **Protect intellectual property.** The simulation engine (`src/phos/synth/`) represents engineering work,
   accumulated research, and the environment in which Atlas is developed. Giving away the implementation creates
   competitive advantages for other companies.

2. **Establish scientific credibility.** Cybersecurity and OT researchers must be able to examine the methodology,
   reproduce published experiments, and challenge the assumptions. A simulator that cannot be questioned is
   indistinguishable from marketing.

3. **Persuade industrial organisations to trust us with real operational data.** Operators will not hand over
   plant data to a black box. They need to see the science, the limitations, and independent scrutiny before
   they consider a controlled evaluation against historical data.

Optimising for just one of these fails the others. Open-sourcing the engine sacrifices IP. Keeping everything
closed sacrifices credibility. Publishing only synthetic benchmarks sacrifices industrial trust.

This ADR records the chosen position: **keep the invention proprietary, make the science inspectable, make the
evidence reproducible, let the real world deliver the verdict.**

## Decisions

### Decision 1 — The simulation engine remains proprietary

`src/phos/synth/` is not extracted to a separate repository. It is not released under MIT or any open-source
licence. The implementation stays inside the PHOS repository under its existing licence terms.

This is a reversal of ADR 0455, which proposed releasing the engine under PolyForm Noncommercial. The new
position is stricter: the code is not public at all. The scientific methodology and example outputs are public;
the generator is not.

**Why not MIT even for the engine alone.** `src/phos/synth/` imports from `phos.eval`, `phos.ontology`, and
`phos.atlas.topology`. Extracting it to a standalone MIT repository would either duplicate those abstractions
(forbidden by Constitution §3.1: one ontology) or create a runtime dependency on PolyForm-licensed code,
defeating the purpose.

### Decision 2 — The scientific methodology is public

The ADRs that describe the simulator are public specifications, not marketing claims. Researchers can read
them and understand:

- How simulated industrial plants are constructed (ADR 0015)
- Which physical principles are represented (ADR 0015, `phos.synth.process`)
- How control logic is modelled (ADR 0015, plant controllers)
- How sensors and actuators behave (ADR 0015, injection hook, true-state record)
- How operational disturbances are generated (ADR 0073, `phos.synth.realism`)
- How attack scenarios are constructed (ADR 0016, intent-based specification)
- How randomisation works (ADR 0015, seed-to-plant mapping)
- How anti-fingerprinting mechanisms operate (ADR 0016, five enforced mechanisms)
- Which assumptions simplify real industrial environments (limitations register)
- Where the simulator is known to be inaccurate (limitations register, anti-bias construction)

**Standard:** Detailed enough that an independent researcher could attempt to implement their own version
from the specification alone. This is a stronger demonstration of scientific openness than publishing a
collection of marketing claims.

### Decision 3 — Example corpora are published

Selected outputs generated by the proprietary simulator are published as fixed datasets with hashes:

| Corpus | Purpose |
|---|---|
| `synth-water-treatment-holdout` | Quiet plant data; false-positive baseline |
| `synth-attack-water-treatment-graded` | Labelled attacks across difficulty levels |
| `synth-attack-water-unknown-master` | Command/re-routing scenario (unknown master) |
| `synth-hostile-malformed-records` | Software robustness example |
| `synth-power-generation-train` | Second plant family, quiet |
| `synth-batch-reactor-holdout` | Batch process, quiet |

Each corpus ships with:
- `telemetry.csv` — prepared-corpus shape `phos.eval.LabelledCsvAdapter` reads
- `topology.toml` — declared subsystem map, format `phos.atlas.topology.load_topology` reads
- `manifest.json` — generation recipe, plant declaration, seeds, digests
- `capture.pcap` — Modbus/TCP control traffic (where applicable)
- SHA-256 digests of every file

**Qualification:** Fixed datasets establish reproducibility of *those particular experiments*, not the fidelity
of the entire simulation engine. Researchers can reproduce scores on fixed files, but cannot regenerate the
generator. That gap is stated plainly.

### Decision 4 — Independent technical audits

A formal **PHOS Independent Research Programme** is established. Selected researchers receive controlled access
to the simulator implementation under confidentiality agreements. Their remit:

- Whether the implementation matches the published specifications
- Whether randomisation genuinely creates meaningful diversity
- Whether attack-generation methodology introduces bias
- Whether simulation models are sufficiently representative
- Whether anti-fingerprinting mechanisms work
- Whether the simulator contains undocumented assumptions

Findings are published, subject to confidentiality terms where agreed.

**Honest limitation:** A confidential audit is not equivalent to public source-code verification. It is a
meaningful step, not the final one.

### Decision 5 — Real-world validation is the ultimate objective

The progression:

| Stage | Objective | Evidence produced |
|---|---|---|
| 1 | Synthetic research | Reproducible simulation results |
| 2 | Independent scrutiny | External technical assessments |
| 3 | Industrial engagement | Relationships with experienced OT operators |
| 4 | Historical plant-data evaluation | Performance against previously unseen real data |
| 5 | Controlled pilot | Demonstrated operational usefulness |
| 6 | Commercial deployment | Customer evidence and measurable value |

Stage 3→4 is the crucial transition. A real industrial operator allowing Atlas to undergo a properly controlled
evaluation against historical operational data is more consequential than another impressive synthetic benchmark.

### Decision 6 — IP boundary matrix

| PHOS asset | Treatment |
|---|---|
| Simulation methodology | Public specification |
| Simulation ADRs | Public |
| Scientific limitations | Public |
| Example datasets | Public, selectively published with hashes |
| Simulation implementation | Proprietary |
| Atlas detection architecture | Proprietary |
| Sentiel detection architecture | Proprietary |
| Commercial deployment infrastructure | Proprietary |
| Independent audit findings | Public, subject to confidentiality |

### Decision 7 — Anti-fingerprinting requirements preserved

All five mechanisms from ADR 0073 remain in force:
1. The generator may not reference the detector
2. Attacks specified by intent, never by signature
3. Every scenario carries real-world provenance
4. A mandatory band of misses exists
5. The method is published including its failures

These live in the public specification.

### Decision 8 — Licensing arrangements require professional review

The existing PolyForm Noncommercial licence (`public/overlay/LICENCE`) applies to the PHOS repository. The
hybrid model (public methodology, proprietary implementation, public example corpora) has not been reviewed
by counsel. Licensing arrangements should be reviewed professionally before publication, particularly where
existing PolyForm restrictions and third-party dependencies are involved.

## Success is

- Researchers can examine the methodology, reproduce published experiments on fixed corpora, and challenge
  the assumptions without access to the generator source.
- Example corpora are published with digests, enabling independent detector testing.
- The Independent Research Programme has at least one external auditor under agreement.
- No frozen public row is overwritten (HAI 646.58, grouped 53.26, distillation 18.72, CERT 6B 0.104).
- P1 remains blocked; no Intelligence/API/UI work starts.
- No claim of ≥70%, 10×, or 2–3/day is made from synthetic results.

## Success is not

- PHOS endorsing any researcher's validation of the simulator.
- A detection rate, recall figure, or FP rate for any real environment derived from synthetic data.
- A replacement for any frozen public row.
- Public source-code verification of the simulator.
- Commercial deployment of Atlas.
