## Context

Two Atlas capabilities are built, wired, tested, and completely unmeasurable.

| Capability | Built | Measured | Blocked by |
| --- | --- | --- | --- |
| Unauthorised-command attribution | yes | **no** — known-station unique lead frozen at 0 of 16 | No public corpus carries command-action ground truth (ADR 0040) |
| The CMMS / work-order join | yes | **no** — has measured nothing, ever | No public corpus ships a maintenance calendar (ADR 0069) |

The synthetic library could not exercise either, and the reason is sharper than "it is synthetic".

**The plants' writes were cosmetic.** `Plant._command_intents` emitted an operator write carrying
`register_count(spec, reported[key])` — the value the setpoint had *already* taken, because
`begin_event` had moved it before the write was rendered. The wire reported the physics rather than
driving it. Deleting a generated capture changed no reading. An attacker whose writes are cosmetic
is an attacker the process never felt, so the command path had nothing real to be aimed at.

**There was no authorisation ground truth.** `grep -rn 'authoris' src/phos/synth/` returned nothing.
`CommandIntent.reason` is free text that `traffic.py` deliberately never puts in a byte — provenance,
not truth.

**There was no maintenance register at all.** "maintenance" appeared in `synth/` only as a benign
event label (`intake_maintenance_stop`).

ADR 0069's rejected alternative is the trap this record has to walk past: *"Synthesise work orders
for HAI to show the join working end to end"* was refused as scoring our own fiction. That refusal
stands. This work is admissible only because the calendar is generated by a process that
**structurally cannot see the attack schedule**, on a plant that is synthetic end to end, and
because it produces no measurement. If those three things were not true it would be the rejected
alternative wearing a different hat.

## Decisions

### Decision 1 — The anti-bias construction is five enforced mechanisms, not five intentions

The central risk is circularity: if one author writes both "an attack looks like this" and "the
detector looks for that", a good score measures the agreement of two beliefs. PHOS already refuses
this one level down — topology is **declared** and never clustered, peer groups come from the
**directory** and never from behaviour. These are the same refusal one level up.

Each mechanism fails a build. `tests/synth/test_anti_bias.py`, 30 tests.

| # | Mechanism | How it fails |
| --- | --- | --- |
| 1 | The generator may not reference the detector | AST scan of every module under `src/phos/synth/` for imports of `phos.atlas` / `phos.sentiel` |
| 2 | Attacks are specified by intent, never by signature | Scenario prose scanned against **Atlas's own `__all__`**; `Scenario` has no magnitude-shaped field |
| 3 | Every scenario carries real-world provenance | `Provenance` validator rejects `atlas`, `sentiel`, `interesting`, `tbd`, `todo`, `n/a` |
| 4 | A mandatory band of cases the detector should miss | A run producing no below-floor attacks and no attack-like benigns fails |
| 5 | The method is published including its failures | `docs/synthetic-harness-method.md` must carry four named sections; the limitations section must exceed 400 words |

**Mechanism 1 has exactly one declared exception, named symbol by symbol.** `phos.synth.topology`
imports `SCHEMA_VERSION`, `Subsystem` and `SubsystemMap` from `phos.atlas.topology` so a generated
corpus ships its declared subsystem map in the format a real corpus does. That is a *declaration
format* — no feature, no score, no threshold, no finding. The allowlist names the module **and the
three symbols**; any fourth name from that same module fails. A further test asserts the exception
is actually used, so a dead entry cannot sit there widening the hole. The four modules this work
added carry **no** exception and are held to zero separately.

**The mechanisms were mutation-tested.** Adding `from phos.atlas.packet import COMMAND_COUNT` to
`command.py` turned two tests red. Rewriting a scenario goal as "make the write_command_share
deviation exceed its learned baseline threshold" turned two more red. Adding an `attack_windows`
parameter to `plan_maintenance` turned a fifth red. A guard that cannot fail is not a guard.

### Decision 2 — A write is applied before the controllers run, so it causes something

`phos.synth.command` adds a `CommandSource`, consulted once per sample **before** `control()`. A
write is applied to the plant's own state, so the setpoint it moves is the setpoint the loop closes
on at its next scan, and the loop moves the true state.

The test that matters is the counterfactual: the same run with the write removed reaches a
different true state. A cosmetic write leaves the two identical.

**Rejected: coordinating a write with a separate reading injection**, which is what the existing
command attacks do — `_build_setpoint_attack` pins the setpoint with a `ReadingBlend` and emits
writes chosen to agree numerically. That is two mechanisms bolted together by hand, and it is the
construction that made the wire deletable.

**Restricted to setpoints.** An actuator write is refused with a message pointing at
`phos.synth.injection`, which already models forcing a final control element. Silently doing
nothing would be a command that quietly did nothing.

### Decision 3 — Authority is declared by the plant; a scenario cannot label its own commands

`WriteAuthority` is part of a `PlantDescription`: which device may write which signal. The
authorisation recorded against an observed write is **derived** from that declaration.
`PlannedWrite` has no authorisation field, and a test asserts it.

Granting exactly one station produces three cases:

| Issuer | Authorisation | On the learned graph |
| --- | --- | --- |
| `hmi` | authorised | known station |
| `scada` | **unauthorised** | known station — the compromised legitimate host |
| `engineering` | unauthorised | unknown master (the ADR 0027 shape) |

The middle row is the one no existing construction could express, and it is the hard case.

**A plant with no declared authority refuses to record one** rather than defaulting a device to
either answer.

### Decision 4 — Ground truth is kept apart from the wire, because on a real wire it is

`IssuedCommand` records what was commanded and whether it was authorised. `CommandIntent` is what a
capture shows. An authorised write and an unauthorised one are **the same bytes**.

The discriminating test builds two plants differing *only* in declared policy, confirms the ground
truth differs, and asserts the rendered frames are byte-identical. Comparing a run against itself
would have proved nothing.

### Decision 5 — The maintenance calendar cannot see the attacks, and the signature is the proof

`plan_maintenance(rng, spec, assets, practice)`. No attack schedule, no scenario, no window list,
and `maintenance.py` imports nothing that could supply one. Both are asserted.

Coverage is therefore a **collision between two independent schedules**, which is what it is in a
real plant. Across three seeds of the same 72-hour patient-adversary run: seeds 7 and 11 produced
**zero** attacker writes inside a sanctioned window; seed 23 produced **177**. That spread is the
construction working. A calendar laid out around the attacks would have produced coverage every
time, and the resulting "the CMMS join changes the ranking" would have been a restatement of its
author's intent.

**The exports are written by hand and read by the real adapter.** `maintenance.py` does not import
`phos.atlas.cmms`; the SAP and Maximo column names are literals, and the test loads what it writes
through `load_work_order_export`. Same argument `traffic.py` makes for building Modbus with
`struct`. A share of orders carry non-sanctioning statuses, so ADR 0069 D5's refusal is exercised
by data rather than by a fixture.

### Decision 6 — Operational realism is additive and off by default

`phos.synth.realism` supplies grade changes, ambient and seasonal drift, equipment ageing and
fouling, benign operator interventions, sensor faults and calibration drift that are **not**
attacks, comms dropouts and retransmissions, and startup/shutdown transitions. All benign, several
deliberately shaped to resemble attacks.

A `RealismProfile` at its defaults produces nothing, so every corpus generated before this existed
is reproduced byte for byte. `plan_realism` takes no attack schedule either.

### Decision 7 — The batch reactor gets nothing

It declares no control network, and the encyclopedia already records that expanding command attacks
onto it would be fiction. It stays the control case where Atlas is deaf to commands by
construction. `scenarios_for("batch-reactor")` returns empty, and a test pins it.

### Decision 8 — Nothing here is a measurement, and the refusals are mechanical

- No row appended to `eval_runs/log.jsonl`.
- `templates.py` matchers and priors not edited.
- `configs/attacks/08-water-unknown-master.toml` not grown.
- `dataset library/`, `library/ot.py`, `library/it.py` untouched.
- `discover_labelled_command_corpora` still returns empty;
  `test_this_repository_holds_no_labelled_command_corpus` still passes. The harness is deliberately
  **not** registered as a corpus in `data/registry.json`.
- `discover_work_order_exports` still returns empty for public corpora.
- HAI Mahalanobis 646.58, grouped 53.26, distillation 18.72, CERT 6B 0.104 untouched.
- Command-lead stays **0 of 16** and **1 of 4**, unpooled. Nothing here moves either: they are
  facts about *public* data.
- ADR 0014's `test_maintenance_and_an_attacker_remain_indistinguishable_to_the_evidence` still
  passes. This work does **not** claim to have separated a commissioning engineer from an intruder.

## Consequences

**Gained — the two dead capabilities can now be exercised.** The diagnostic
(`scripts/diagnose_synthetic_harness.py`) runs Atlas end to end on an adversary whose write really
moved the process: the graph comparison produces `unexpected_command_function` on the
`scada → plc_outlet` link, the issuer classifies as a known station from the learned graph, and the
issued write is recorded as unauthorised in ground truth the wire does not carry. The CMMS inlet has
been fed by a generated SAP PM export, read by the real adapter, and promoted into the stamped
`work-order:work_order:` evidence a template already spends. Neither had ever run.

**Gained — the covered-window case is constructible.** ADR 0014 and ADR 0069 both name an attacker
operating inside a sanctioned window as the case that decides whether maintenance is an explanation
or a verdict. It now exists, and it arrived by coincidence rather than by placement.

**Cost — nothing is measured, and that is not a formality.** Every number the diagnostic prints
describes our model of a plant, our idea of an adversary, and our invention of a maintenance
practice. The honest limitations section names nine ways this is likely to mislead, including the
one that matters most: **the coverage rate is the number most likely to be badly wrong, and it is
exactly the number the CMMS join's value depends on.**

**Cost — the harness is more tempting to quote than its predecessor**, precisely because it now
exercises more machinery. That is why Decision 8 is mechanical rather than a warning.

**Not done, deliberately.** The realism effects are generated and tested but are not yet wired into
the plants' `_sense` and `traffic.py` paths; `plan_realism` returns a plan a future change applies.
Wiring it means touching the sensor model and the pcap renderer, which is a change to how every
existing corpus is produced, and it deserves its own record rather than riding along with this one.
The Atlas-side ranking comparison (does a work order change *which* explanation leads?) was also
not run: it needs the full reasoning engine with a fitted calibrator over a generated corpus, and
reporting a ranking change on eleven synthetic windows would be an anecdote dressed as a result.

## Alternatives considered

- **Register the harness in `data/registry.json` as a labelled command corpus.** Rejected. It would
  turn ADR 0040's tripwire green on synthetic data, which is the precise lie that tripwire exists
  to prevent.
- **Tune the maintenance practice until coverage reliably happens.** Rejected, and it was tempting
  when two of three seeds produced none. Tuning the calendar against observed coverage is the
  circularity with an extra step.
- **Let a scenario declare its own writes unauthorised.** Rejected. The label would be a
  restatement of the author's intent rather than a property of the plant.
- **Give the batch reactor a control network so all three plants are uniform.** Rejected — it is
  the control case, and uniformity is not worth losing it.
- **Mix causal writes and the legacy echo in one run.** Rejected. It would put a causal write and a
  cosmetic one in the same capture, and the difference between them is what this layer exists to
  make real.
- **Report a lead rate on the synthetic corpus.** Rejected. A breaking-harness ordinal is not a
  field detection rate, and the programme lock forbids quoting one as such.

## When to revisit

When a design partner supplies a real Modbus capture with command-action windows and a real CMMS
export for the same period. At that point every mechanism here becomes testable against something
that is not ours, and the honest limitations section becomes a list of predictions to check rather
than a list of worries. Until then, P1 — the design-partner conversation — remains the next real
step, and nothing in this record advances it.
